# Socket 群聊：三栏界面、注册登录、data 保存

两个 cpp 合编成一个 `chat.exe`，共用一个接口头文件：

- `chat.cpp`：聊天核心。包含账号注册登录、data 读写、协议编解码、群 ID、成员管理、内存聊天记录、排序、未读数、多线程和原生 Socket 收发。
- `ui.cpp`：界面。包含中文输入输出、三栏绘制、方向键选择、表单和登录菜单；收集输入后调用核心接口。
- `chat.h`：`Member`、`Group`、`ChatView` 和接口声明，供两个 cpp 共用。

函数和关键步骤旁都有注释。当前只编译根目录的两个 cpp。交源码时带上 `chat.h`。

当前 `chat.cpp` **共 200 行，包含 include 和注释**。`chat.h` 只放数据类型和接口声明，UI 不包含协议处理、账号读写或群管理实现。下面保留较详细的学习说明。

## 编译与启动

```powershell
.\build.ps1
.\chat.exe
```

也可以直接双击 `chat.exe`。先选择：

```text
1. 登录已有账号
2. 注册新账号
0. 退出
```

**注册**：填写昵称、尚未注册的监听端口、本机 IPv4，并保存到 data。新建的账号会直接进入聊天界面。同机测试 IP 留空，默认 `127.0.0.1`。

**登录**：程序列出 data 中的所有账号，选一个序号进入。昵称、IP、监听端口和群表都从文件读取，不再询问是否改名。注册后的昵称和端口固定，没有改名入口，也没有密码。

旧 data 中的账号会直接出现在登录列表，原有文件没有删除。也可直接选择已注册端口登录：

```powershell
.\chat.exe 9001
```

命令行不再接收昵称，`chat.exe 9001 Alice` 不属于当前用法。新账号需先从注册菜单创建。

跨电脑注册时填写自己的局域网 IPv4，加人时填写对方实际 IPv4。防火墙询问时允许本次实验通信。

## 三栏操作

```text
左侧群列表       中间聊天区                 右侧系统操作
上下选择群       消息和输入框               创建群组 / 添加成员
显示未读数       中文、英文、长消息换行     查看成员 / 退出程序
```

窗口至少 80 列、26 行，建议 120 列、30 行。登录/注册页按提示输入数字；进入三栏界面后，全程用方向键和 Enter：

| 按键 | 左栏：群列表 | 中栏：聊天 | 右栏：系统操作 |
|---|---|---|---|
| ← / → | 在左、中、右三栏之间切换，标题方括号标出当前栏 | 同左 | 同左 |
| ↑ / ↓ | 选择群，蓝底表示指向的群 | 上下翻聊天记录 | 选择功能、表单字段或成员 |
| Enter | 打开选中的群，并进入聊天输入 | 发送消息 | 执行选项；字段中按 Enter 到下一项 |

1. 按 → 到右栏，选择 **创建群组**，Enter 打开表单；输入群名，Enter 移到 **确认**，再按 Enter 建群。
2. 在右栏选 **添加成员**，依次填写 IP、监听端口、昵称；每项 Enter 到下一项，最后选择 **确认**。
3. 按 ← 回中栏，输入消息，Enter 发送。离开中栏或收到新消息时，未发送草稿都会保留。
4. 按 ← 到左栏，上下选择群，Enter 打开；`*` 标出当前打开的群，括号显示其他群的未读数。
5. 右栏选 **查看成员**，上下翻成员，Enter 返回菜单。中间聊天继续显示。
6. 表单可用上下键选择字段修改，或选择 **取消**；右栏选 **退出程序** 后 Enter 退出。

让 Bob 先注册并上线，例如昵称 Bob、端口 9002；Alice 建群后，在右侧添加 `127.0.0.1`、`9002`、`Bob`。Bob 收到群资料就能回复。三人聊天同样把第三个人加入成员表。

成员应先在线；本骨架没有离线补发和离线群表同步。

## 中文输入

UI 使用 `ReadConsoleInputW` 接收控制台提交的 Unicode 字符，不再使用 `_getwch()` 临时清零输入模式。没有提交文字的输入法转换键不会触发重画，避免干扰选词。

使用中文输入法输入并确认选词，再按 Enter 发送；右侧群名和成员昵称同样支持中文。Windows 控制台用 UTF-16，网络与文件用 UTF-8，转换集中在 `utf8`、`wide` 两个函数。

代码验证覆盖控制台模式保持、Unicode 提交事件和中文收发；输入法自身的候选窗仍由 Windows 管理。API 说明见 [微软 ReadConsoleInput 文档](https://learn.microsoft.com/en-us/windows/console/readconsoleinput)。

## UI 与核心如何配合

只保留键盘操作入口：`focus` 表示当前栏，`page` 表示右栏页面，`choice` 表示右栏选项。`system_items` 提供当前页面的选项，`key_input` 移动选择和接收文字，`confirm` 处理 Enter。

UI 收集输入后调用核心，只有 6 个对外接口：

| 接口 | 用途 |
|---|---|
| `chat_accounts()` | 定位 exe 旁的 data，按端口返回已注册账号 |
| `chat_account(account, create)` | `true` 注册，`false` 从文件恢复固定身份和群表 |
| `chat_start()` | 初始化 Winsock、监听账号端口、启动接收线程 |
| `chat_action(action, id, text, member)` | 统一处理建群、加人、切群、发消息 |
| `chat_snapshot()` | 加锁取得一份显示数据，并清除核心的更新标记 |
| `chat_stop()` | 唤醒接收线程，等待它退出，关闭 Socket 和 Winsock |

`ChatView` 保存账号、当前群 ID、群列表和状态提示。每个 `Group` 自己保存成员、消息、未读数和完整群资料文本。这样不用再同步几张独立的消息表、未读表。

`Group::members` 用 `IP:端口` 查成员；`Group::messages` 使用 `multimap`，键是完整 CHAT 文本，值是整理好的显示文字。`multimap` 自动排序并允许相同的键，所以连续收到两条完全相同的消息也会保留两条。

UI 每次最多等键盘 100ms，再调用 `chat_snapshot()`。副本里的 `changed` 为真时才重画；绘图都在 UI 主线程完成。核心更新数据、UI 读取副本由一把互斥锁保护。

聊天输入中的文字统一作为消息正文，系统操作通过右栏菜单执行。

## data 与聊天记录

data 固定在 **chat.exe 所在文件夹**，不随启动时的工作目录变化：

```text
data/
  9001.txt   一个已注册账号的资料、全部群及成员表
  9002.txt   另一个账号的资料
```

文件只包含 Tab 分隔的两类记录：

```text
SELF  本机IP  本机监听端口  昵称
GROUP 群ID    群名        成员IP 成员端口 昵称 ……
```

注册创建 SELF；建群、加人、收到群资料时保存群表。已有端口不能重复注册或覆盖，普通登录只读账号资料。名字可以包含空格和中文，不要包含 Tab 或换行。

这是按正常实验输入编写的骨架。请填写有效昵称、IPv4 和 1~65535 的端口，当前没有完整输入校验。

**聊天不写入 data。** 消息保存在各群的 `messages` 中，退出进程后释放，重新登录恢复群表、旧消息为空。最简版移除了每群 200 条的截断，本次运行期间的记录都保留在内存里。

## 网络与协议

一次 TCP 短连接传一条完整文本。发送端循环 `send` 后关闭连接；接收端循环 `recv`，返回 0 表示正文接收完毕，然后交给 `process_packet`。字段间是真正的 Tab：

```text
GROUP 群ID 群名 成员IP 成员端口 昵称 ……
CHAT  群ID 年月日_时分秒 发送者IP 发送者监听端口 正文
```

本机建群、加人、发消息和远端收到消息都使用同一个 `process_packet`。GROUP 更新群资料并保存；CHAT 解析发送者地址、查昵称、把消息放进对应群并增加未读数。切群时清除该群未读数。

群 ID 用标准库 `hash<string>` 对 `年月日_时分秒|创建者IP:端口` 计算，再取为 32 位数。省去了手写哈希循环。已有群 ID 直接从 data 读取，不重新计算；同账号不在同秒建两个群仍是使用约定，代码没有间隔检查。

同群的 CHAT 文本开头类型和 ID 相同，后面是固定格式的年月日时分秒，因此字符串排序就是先按时间排序，同秒再按地址、端口文本、正文排序。

接收线程用阻塞的 `accept` 等连接。退出时先将 `running` 设为 false，再向本机监听端口建立一次空连接，唤醒 `accept`；接收线程跳过这条空消息并退出，主线程 `join` 后再关闭监听 Socket。

## 核心代码学习顺序

| 函数 | 看懂什么 |
|---|---|
| `read_member` | 读取 IP、端口、昵称；昵称用 getline 保留空格和中文 |
| `endpoint` | 构造 IPv4 地址，htons 转换端口字节序 |
| `save` | 只写 SELF 和群资料文本，完全不写消息 |
| `process_packet` | 识别 GROUP/CHAT，按群 ID 更新数据 |
| `send_to` | socket → connect → 循环 send → closesocket |
| `receive_loop` | accept → 循环 recv → 处理完整消息 |
| `chat_accounts`、`chat_account` | 注册只创建新文件，登录从已有文件读固定身份 |
| `chat_start`、`chat_stop` | 网络初始化、接收线程启动与退出 |
| `chat_action` | 四种操作共用一次加锁和同一套协议处理、群发流程 |
| `chat_snapshot` | 返回副本，使 UI 不直接访问接收线程正在修改的数据 |

`chat_account` 中 `create == exists(path)` 的含义：注册时文件已存在，或者登录时文件不存在，都返回失败。

界面另看 `ui.cpp` 的 `draw`、`confirm`、`key_input` 和 `wmain`。UI 仅把输入转成核心接口参数、按窗口宽度换行、显示数据。
